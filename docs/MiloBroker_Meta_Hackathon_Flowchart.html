FLOWCHART & SYSTEM DESIGN — META GLOBAL AI DEVELOPER HACKATHON

No extra app.
Just WhatsApp.

MiloBroker turns informal WhatsApp chats into structured listings, ranked search, and trackable leads. For the Meta Global AI Developer Hackathon we ship a deterministic, demo-reliable P0 core and layer Meta Muse (closed-weight, via Meta Model API + WhatsApp Cloud API) as the conversational intelligence — without risking the golden path. No Llama open weights.

P0: Deterministic · Reliable · Judged Live P1 / Meta: Muse Spark · Muse Spark 1.1 · WhatsApp Cloud API — Muse-only File: /hackathon/MiloBroker_Meta_Hackathon_Flowchart.html
Hackathon rule respected + Muse-only constraint: Roadmap P2 defers vector DB / agent until P0 is rehearsed. This design keeps deterministic extraction → Search API → Postgres/in-memory as the judged path, and isolates Meta Muse (Spark / Spark 1.1, closed-weight via Meta Model API) as the enhancement lane (ambiguity recovery, voice transcript → structured slots, image understanding, policy-safe moderation). Zero Llama open-weight inference.

Judges score product clarity → working proof → technical credibility. WhatsApp is where India already negotiates rent. Meta provides the transport and the intelligence.

Balanced — Muse		Meta Muse closed-weight (Spark Apr 2026). Frontier-class, lower latency/cost than 1.1. Same API, same tool-calling contract. No open weights.Balanced path: Simple intent, short listings, quick clarifications, and cost-sensitive turns. Router picks Spark vs 1.1 by complexity/latency budget. Muse-only gateway		The only gateway for Muse: OpenAI-compatible Chat/Tool API, streaming, tool_choice auto/required, vision input. Hosted by Meta; no self-host.Glue: Single client for both Muse models. Define search_properties, create_listing_draft, submit_listing, create_lead, handoff_to_human as tools. Deterministic path bypasses this entirely for offline reliability.
Muse Safety / Policy
Safety		Closed-weight system-level safety in Muse (via system instructions + built-in moderation). Task-scoped to Post/Search/Promote for WhatsApp compliance.Guardrails: Pre-filter inputs + post-filter replies/listing descriptions via Muse system policy + task scope. No Llama Guard. Required for WhatsApp bot review.
WhatsApp + Muse combo
Differentiation		Meta owns both transport (Cloud API) and intelligence (Muse) — single vendor, single billing, single review path.Pitch line: “WhatsApp is where India negotiates rent. Muse is the intelligence that turns that chat into structured, ranked, trackable inventory — from the same Meta platform.”

How we keep P0 reliable while showing Meta Muse differentiation

Pattern: Deterministic first, Muse second. Try regex/alias extraction (covers “2 BHK / 45k / Whitefield / PG sharing”) first. If confidence low or message has photos/voice/long context → call Muse Spark / 1.1 via Meta Model API. Judges see fast, explainable extraction; Muse visibly improves hard cases.
Policy compliance: Since Jan 15 2026 Meta prohibits general-purpose bots on WhatsApp. MiloBroker is task-scoped to Post / Search / Promote with handoff_to_human → Muse system instructions enforce it — compliant.

Voice (P1-05) — WhatsApp does NOT auto-transcribe

Webhook delivers audio {id, mime_type: audio/ogg, voice:true} — not text. Optional transcript field is best-effort only, not relied on. Backend does: GET /{media-id} → download OGG → Muse transcription → visible transcript → same SearchRequest as text. Fails twice → hide voice, show as “next”.

Media (P1-06)

One image to draft; Muse Spark 1.1 vision describes furnishing/sharing; stored with draft, not auto-published until confirm.

Empty & error

Empty → refinement chips, no invented inventory. API failure → seeded fallback + “try again”. Muse outage → deterministic path still demos.

Demo script (timed, ~4:30)

  1. Problem (30s) — App-hopping for homes. MiloBroker: “No extra app. Just WhatsApp.”
  2. Post (60s) — Owner posts PG in Whitefield → draft → confirm → active.
  3. Admin (15s) — Show active/pending → approved (or pre-active seed).
  4. Search (60s) — “2 BHK near Whitefield under 45k” → slots visible → 2–3 ranked cards.
  5. Lead (30s) — Tap card → lead → admin shows lead + source query.
  6. Meta Muse lane (45s) — Same query via voice transcript + Muse Spark 1.1 vision (photo understanding), Muse Safety moderation, long PG context via Spark 1.1. Differentiation, not risk. Muse-only.
  7. Model & next (30s) — Post free, Search paid, Promote premium (builders, next). “Simulator is fallback; Cloud API is the channel.”
Kill-switches: WhatsApp down → simulator; voice fails twice → text; DB unstable → seeded provider; posting incomplete at 60% → perfect Search→Lead and describe Post as partial.
